\textbf{Core Architectural Takeaway:} Classical sorting algorithms ($\mathcal{O}(n \log n)$) arrange scalar values along a 1D axis ($a_1 \le a_2 \dots$). In contrast, multi-agent execution graphs require scheduling a \textbf{partially ordered set} with zero, one, or multiple asynchronous parent promises. \textbf{Topological Sorting} is the only algorithm with $\mathcal{O}(V+E)$ complexity that guarantees causal precedence, detects deadlocks, and unlocks parallel execution.

\begin{frame}[t]{How ORPO Works: Preference Alignment and Quality Gating}
\vspace{-0.55em}

% Top Concept Banner: What is ORPO & Why as a Reward System?
\begin{tcolorbox}[
  enhanced, arc=2.5pt, colframe=lavenderDark!90, colback=lavenderLight!45,
  boxrule=0.55pt, left=4pt, right=4pt, top=1.8pt, bottom=1.8pt
]
\fontsize{4.8}{5.8}\selectfont
\textbf{\color{lavenderDark}\faBalanceScale\; What is ORPO \& Why is it Used Here as a Reward System?}\\[0.5pt]
$\bullet$\;\textbf{What is ORPO?} \textbf{Odds Ratio Preference Optimization (ORPO)} is an integrated \textbf{single-stage reward and alignment algorithm}. Traditional RLHF (PPO) requires training a separate reward model and keeping a frozen reference model in GPU memory (heavy, slow, and unstable).\\
$\bullet$\;\textbf{Why in PrismSpace?} In multi-agent swarms, LLMs can hallucinate invalid tools or malformed code. ORPO acts as an \textbf{internal reward filter}: it mathematically rewards compliant trajectories ($y_w$) and penalizes bad responses ($y_l$) during fine-tuning, eliminating the need for an external reward model.
\end{tcolorbox}

\centering
$\mathcal{L}_{\mathrm{ORPO}} = \mathcal{L}_{\mathrm{SFT}} + \lambda_{\mathrm{OR}}\,\mathcal{L}_{\mathrm{OR}}$\\[1pt]
$\mathcal{L}_{\mathrm{OR}} = -\log \sigma\!\left(\log \frac{\mathrm{odds}(y_w|x)}{\mathrm{odds}(y_l|x)}\right), \quad \mathrm{odds}(y|x) = \frac{P(y|x)}{1 - P(y|x)}$\\[1.5pt]
\raggedright
$\bullet$\;\textbf{Implicit Reward Gradient:} $\text{odds}(y|x)$ measures the probability of generating a token vs not generating it. When $y_l$ is chosen, loss explodes, forcing logits of $y_w \gg y_l$.\\
$\bullet$\;\textbf{Runtime Impact:} The model naturally generates schema-compliant tool calls and suppresses hallucinations before writing to PrismDB.
