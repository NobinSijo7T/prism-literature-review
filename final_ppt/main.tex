\fontsize{8.6}{12.6}\selectfont\sffamily\color{lavenderDeep}
  \textbf{\fontsize{10.2}{13.0}\selectfont\color{lavenderDark}PrismSpace} is an interactive, \textbf{web-based multi-agent intelligence platform} and workspace website that allows users to orchestrate autonomous AI swarms directly from modern web browsers. It converts natural-language user goals into dependency-aware \textbf{Directed Acyclic Graphs (DAGs)} for parallel sub-task execution. Built as a responsive web application (Next.js 15, React 19) accessible from any browser with zero local setup, it features an interactive visual DAG swarm visualizer with real-time token and step streaming. The platform pairs Groq, OpenAI, and NVIDIA NIM with standardized tool connectivity via Model Context Protocol (MCP), while storing all session state locally in client-side IndexedDB (\texttt{PrismDB}) with human-in-the-loop approval gates for privacy and safety.
\end{tcolorbox}
\end{minipage}

\section{Introduction}

\begin{frame}{Introduction}
\vspace{0.25cm}
\begin{block}{Overview}
\normalsize
While modern development tasks span code, browsers, databases, and \textbf{APIs} (Application Programming Interfaces), uncoordinated multi-agent workflows suffer from context fragmentation, runaway loops, and tool hallucinations. To address these challenges, PrismSpace introduces a unified developer workspace featuring \textbf{multi-agent orchestration}, sandboxed \textbf{MCP} (Model Context Protocol) tool execution with strict \textbf{ReAct} (Reasoning and Acting) loops, \textbf{HITL} (Human-in-the-Loop) safety, and \textbf{ORPO} (Odds Ratio Preference Optimization) preference alignment.
\end{block}
\end{frame}

\section{Objectives}

\begin{frame}{Objectives}
\vspace{0.25cm}
\begin{block}{Core Objectives}
\normalsize
The primary objective is to enable structured task execution through \textbf{DAG} (Directed Acyclic Graph)-based task decomposition, \textbf{MCP} (Model Context Protocol)-enabled multi-agent \textbf{ReAct} (Reasoning and Acting) orchestration, and \textbf{ORPO} (Odds Ratio Preference Optimization) preference optimization. Additionally, the system ensures reliable and cost-effective operation through supervised \textbf{LLM} (Large Language Model) routing and human-in-the-loop validation.
\end{block}
\end{frame}

\section{Problem statement}

\begin{frame}{Problem Statement}
\vspace{0.25cm}
\begin{block}{Problem Formulation}
\normalsize
Because ungrounded \textbf{LLM} (Large Language Model) agents risk hallucinating tool results and executing unsafe actions, the system takes developer task prompts, workspace states, and \textbf{MCP} (Model Context Protocol)/\textbf{HITL} (Human-in-the-Loop) configurations as its primary \textbf{inputs}. Through an orchestration \textbf{method} integrating sandboxed \textbf{MCP} \textbf{ReAct} (Reasoning and Acting) loops, \textbf{ORPO} (Odds Ratio Preference Optimization), supervised \textbf{LLM} routing, and Isolation Forest anomaly detection with \textbf{HITL} oversight, it converts these tasks into dependable \textbf{outputs} consisting of verified artifacts, \textbf{ReAct} execution traces, and cost telemetry.
\end{block}
\end{frame}

&
Proposes \textbf{Average-Reward Adjusted Discounted \textbf{RL} (Reinforcement Learning) (ARAD-\textbf{RL})}, bridging the gap between discounted and average reward criteria in infinite-horizon \textbf{MDPs} (Markov Decision Processes). &
\textbf{Advantages:}
\begin{itemize}\itemsep0.05em\topsep0.1em
\item Eliminates infinite-horizon return explosion while preserving policy convergence.
\item Improves long-term steady-state throughput in continuous scheduling tasks.
\item Theoretically sound formulation for continuous agent lifecycle optimization.
\end{itemize}
\vspace{-0.2em}
\textbf{Disadvantages:}
\begin{itemize}\itemsep0.05em\topsep0.1em
\item Requires accurate empirical estimation of average reward baseline.
\item Slow convergence in highly non-stationary transition environments.
\item Adds variance to early-stage \textbf{TD} (Temporal Difference) error gradient estimates.
\end{itemize} \\
\hline
\end{tabular}
}

\end{itemize}

\textbf{Advantages:}
\begin{itemize}\itemsep0.05em\topsep0.1em
\item Reference-model-free: eliminates maintaining frozen $\pi_{\text{ref}}$ in memory.
\item Monolithic single-phase training avoids unstable \textbf{PPO} policy optimization.

\begin{frame}{Research Gap}
\vspace{-0.05cm}
\begin{block}{What the surveyed methods already do}
\footnotesize
\textbf{MARL} works address \textbf{CTDE}, role grouping, and ad-hoc coordination. \textbf{ORPO} aligns \textbf{LLM} preferences without reference models, while \textbf{HIAT} leverages human interventions as auxiliary \textbf{RL} signals. \textbf{CPN-HRL} and \textbf{DAG} schedulers optimize cloud task allocation, and \textbf{MHC} formalizes tracking and tracing properties.
\end{block}
\vspace{0.08cm}
\begin{block}{Limitations observed in those papers}
\footnotesize
Coordination benchmarks focus on gaming (\textbf{SMAC}, Overcooked) rather than filesystem/\textbf{API} tooling. \textbf{ORPO} lacks grounding in \textbf{MCP} \textbf{ReAct} tool traces, while \textbf{HIAT} targets continuous robotic control instead of code execution. Cloud schedulers assume static \textbf{DAGs} or slow metaheuristics ill-suited for real-time \textbf{LLM} routing.
\end{block}
\vspace{0.08cm}
\begin{block}{Why PrismSpace is required}
\footnotesize
No reviewed system jointly grounds tool observations, aligns policies on agent trajectories, dynamically routes heterogeneous \textbf{LLMs}, and enforces human-in-the-loop safety gates within a unified developer workspace.
\end{block}
\end{frame}

% STEP 1: PROMPT PARSING & TASK REPRESENTATION

\begin{frame}[t]{Algorithm: Step 1 -- Understand the User Prompt}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 1: Prompt Parsing and Structured Representation}
\vspace{0.15em}

\begin{algolist}
  \item[1.1] Read the user's natural-language prompt and identify the main goal.
  \item[1.2] Retrieve persistent session context and workspace history from browser IndexedDB (\texttt{PrismDB}):
    \begin{algosublist}
      \item[1.2.1] Load relevant conversation history, saved preferences, and agent state.
      \item[1.2.2] Resolve referenced files, repositories, and available permissions.
    \end{algosublist}
  \item[1.3] Build a structured task record containing the goal, constraints, context, allowed tools, and expected output.
    \begin{algosublist}
      \item[1.3.1] Record deadlines, output format, and other task constraints.
      \item[1.3.2] Attach the MCP tools and permissions required for execution.
    \end{algosublist}
  \item[1.4] Perform input boundary and security screening:
    \begin{algosublist}
      \item[1.4.1] Check input size and screen for prompt-injection patterns.
      \item[1.4.2] Mark file, email, or other state-changing actions for user approval.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 2: INTENT CLASSIFICATION & CAPABILITY PROFILING
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 2 -- Classify the Request}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 2: Intent Classification and Capability Check}
\vspace{0.15em}

\begin{algolist}
  \item[2.1] Classify the prompt into a functional domain such as automation, document work, research, or coding:
    \begin{algosublist}
      \item[2.1.1] Extract semantic and keyword features from the prompt.
      \item[2.1.2] Use the intent classifier to select the most likely domain.
    \end{algosublist}
  \item[2.2] Profile required system capabilities and operational risk levels:
    \begin{algosublist}
      \item[2.2.1] Identify required resources, such as web search, file access, or terminal execution.
      \item[2.2.2] Separate read-only work from actions that need approval.
    \end{algosublist}
  \item[2.3] Select optimal execution pathway:
    \begin{algosublist}
      \item[2.3.1] Send simple requests directly to one model.
      \item[2.3.2] Send complex requests to the DAG planner for decomposition.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 3: DAG DECOMPOSITION & MODEL ROUTING
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 3 -- Plan and Route the Task}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 3: DAG Decomposition and Model Routing}
\vspace{0.15em}

\begin{algolist}
  \item[3.1] Deconstruct objective into Directed Acyclic Graph $\mathcal{G} = (V, E)$:
    \begin{algosublist}
      \item[3.1.1] Create one vertex for each atomic task and define its expected output.
      \item[3.1.2] Connect tasks with directed edges when one task depends on another's output.
      \item[3.1.3] Hold a dependent task until all required inputs are available.
    \end{algosublist}
  \item[3.2] Compute topological task execution schedule $\pi = \mathrm{TopologicalSort}(\mathcal{G})$:
    \begin{algosublist}
      \item[3.2.1] Find independent tasks that can run in parallel ($K \le 3$).
      \item[3.2.2] Release dependent tasks when their parent tasks finish.
    \end{algosublist}
  \item[3.3] Select a model for each sub-task by balancing cost, latency, and quality:
    \vspace{-0.2em}
    $$\text{Provider}^* = \arg\min_m \Big(\lambda_{\text{cost}} \, \text{Cost}_m + \lambda_{\text{latency}} \, \text{Latency}_m\Big) \quad \text{s.t. } \text{Quality}_m \ge \tau$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Meaning:}\enspace Choose the lowest-cost and lowest-latency model that still meets the required quality threshold.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[3.3.1] Use fast backends for simple or latency-sensitive tasks.
      \item[3.3.2] Use stronger models for reasoning, research, and code generation.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 4: TASK ASSIGNMENT & AGENT SELECTION
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 4 -- Task Assignment and Agent Selection}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 4: Role-Based Task Assignment and Dispatching}
\vspace{0.15em}

\begin{algolist}
  \item[4.1] Check the specialist-agent registry and their capability profiles:
    \begin{algosublist}
      \item[4.1.1] Review each agent's role, instructions, and assigned tools.
      \item[4.1.2] Check worker availability before dispatch.
    \end{algosublist}
  \item[4.2] Match each sub-task to the agent with the closest capability profile:
    \vspace{-0.2em}
    $$\text{Agent}^* = \arg\max_{a \in \mathcal{A}} \; \mathrm{CosineSimilarity}\big(\mathbf{Req}(v_i), \, \mathbf{Cap}(a)\big)$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Meaning:}\enspace Compare the task requirements with each agent's capabilities and choose the best match.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[4.2.1] Send information-gathering tasks to the Researcher.
      \item[4.2.2] Send software tasks to the Coder.
      \item[4.2.3] Send checking and policy tasks to the Validator.
    \end{algosublist}
  \item[4.3] Manage task lifecycle states in dispatcher queue:
    \begin{algosublist}
      \item[4.3.1] Keep tasks in \texttt{PENDING} until their dependencies finish.
      \item[4.3.2] Move ready tasks to \texttt{READY} and dispatch them.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 5: AGENT COMMUNICATION & DECISION MAKING
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 5 -- Agent Communication and Decision Cycle}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 5: Agent Decision Cycle and Inter-Agent Communication}
\vspace{0.15em}

\begin{algolist}
  \item[5.1] Run a ReAct cycle for each dispatched agent:
    \vspace{-0.2em}
    $$\text{State } s_t \;\longrightarrow\; \text{\textbf{Observe}} \;\longrightarrow\; \text{\textbf{Reason}} \;\longrightarrow\; \text{\textbf{Act}} \;\longrightarrow\; \text{\textbf{Reflect}}$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Meaning:}\enspace Observe the task, reason about the next step, act with a tool or response, and reflect on the result.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[5.1.1] \textbf{Observe:} Read the task, constraints, and parent outputs.
      \item[5.1.2] \textbf{Reason:} Choose the next operation.
      \item[5.1.3] \textbf{Act:} Call an MCP tool or generate an answer.
      \item[5.1.4] \textbf{Reflect:} Check the result and correct local errors.
    \end{algosublist}
  \item[5.2] Transmit intermediate artifacts via DAG edge message passing:
    \begin{algosublist}
      \item[5.2.1] Pass verified outputs from completed tasks to their dependent tasks.
      \item[5.2.2] Pass only relevant artifacts to limit context growth.
    \end{algosublist}
  \item[5.3] Synchronize shared state via local blackboard memory:
    \begin{algosublist}
      \item[5.3.1] Save task state, conversation turns, and file references in \texttt{PrismDB}.
      \item[5.3.2] Notify dependent workers when a task completes.
    \end{algosublist}
\end{algolist}
\end{frame}

      \item[6.1.2] Split the objective into independent and dependent sub-goals.
      \item[6.1.3] Build the DAG and add capability tags.
      \item[6.1.4] Select models and enqueue the topological schedule.
    \end{algosublist}
  \item[6.2] Execute Assistant Agent workflow (Productivity \& Communication):
    \begin{algosublist}
      \item[6.2.1] Retrieve preferences and reference documents.
      \item[6.2.2] Create a structured draft or summary.
      \item[6.2.3] Use Google Workspace tools when required.
      \item[6.2.4] Verify the draft and request approval before sending it.
    \end{algosublist}
\end{algolist}
\end{frame}

\begin{algolist}
  \item[7.1] Execute Researcher Agent workflow (Information Retrieval \& Synthesis):

  \item[7.2] Execute Coder Agent workflow (Software Synthesis \& Execution):

      \item[7.2.2] Run tests or scripts in the terminal and inspect errors.
      \item[7.2.3] Fix syntax and runtime problems using test feedback.
    \end{algosublist}
  \item[7.3] Execute Validator Agent workflow (Quality Auditing \& Safety Gate):
    \begin{algosublist}
      \item[7.3.1] Check outputs against safety, format, and functional requirements.
      \item[7.3.2] Return \textbf{PASS} for valid output or \textbf{FAIL} with diagnostics.
    \end{algosublist}
\end{algolist}
\end{frame}

\begin{frame}[t]{Algorithm: Step 8 -- Standardized Tool Execution via MCP}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 8: Standardized Tool Execution via Model Context Protocol}
\vspace{0.15em}

\begin{algolist}
  \item[8.1] Interface agents to external tools via Model Context Protocol (MCP):
    \begin{algosublist}
      \item[8.1.1] Use JSON-RPC for consistent client-server communication.
      \item[8.1.2] Discover tool schemas, inputs, and return types at runtime.
      \item[8.1.3] Keep agent logic independent of tool implementation details.
    \end{algosublist}
  \item[8.2] Orchestrate multi-domain tool execution ecosystem:
    \begin{algosublist}
      \item[8.2.1] \textbf{System \& Dev Tools:} Filesystem, terminal, and GitHub.
      \item[8.2.2] \textbf{Productivity Tools:} Gmail and Google Drive.
      \item[8.2.3] \textbf{Web Intelligence:} Browser search and document retrieval.
    \end{algosublist}
  \item[8.3] Enforce Human-in-the-Loop (HITL) authorization policy:
    \begin{algosublist}
      \item[8.3.1] Allow read-only queries to run automatically.
      \item[8.3.2] Request approval for file changes, email sending, or other state changes.
    \end{algosublist}
\end{algolist}
\end{frame}

\begin{frame}[t]{Algorithm: Step 9 -- Context Compaction and Shared Memory}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 9: Context Compaction and Shared Memory Management}
\vspace{0.15em}

\begin{algolist}
  \item[9.1] Address context window constraints and token consumption limits:
    \begin{algosublist}
      \item[9.1.1] Keep the active context within the model's token limit.
      \item[9.1.2] Reduce unnecessary history to control latency and attention cost.
    \end{algosublist}
  \item[9.2] Compact the context by keeping verified outputs and removing stale or repeated content.
    \begin{algosublist}
      \item[9.2.1] Forward only verified parent outputs to dependent tasks.
      \item[9.2.2] Remove redundant logs, drafts, and intermediate reasoning.
    \end{algosublist}
  \item[9.3] Persist global execution state using client-side database (\texttt{PrismDB}):
    \begin{algosublist}
      \item[9.3.1] Save session turns, task graphs, and tool logs in IndexedDB.
      \item[9.3.2] Preserve local state for privacy and recovery after failure.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 10: ORPO PREFERENCE MODEL & QUALITY ASSERTION
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 10 -- ORPO Preference Model \& Verification}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 10: Single-Stage Preference Alignment (ORPO) and Verification}
\vspace{0.15em}

\begin{algolist}
  \item[10.1] Train the response-quality model with chosen and rejected examples using ORPO:
    \vspace{-0.25em}
    $$\mathcal{L}_{\mathrm{ORPO}} = \mathcal{L}_{\mathrm{SFT}} + \lambda_{\mathrm{OR}} \cdot \mathcal{L}_{\mathrm{OR}} \quad \text{where} \quad \mathcal{L}_{\mathrm{OR}} = -\log \sigma \left( \log \left[ \frac{\mathrm{odds}_\theta(y_w \mid x)}{\mathrm{odds}_\theta(y_l \mid x)} \right] \right)$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Meaning:}\enspace Combine normal supervised loss with a preference loss that favors the chosen response $y_w$ over the rejected response $y_l$.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[10.1.1] Increase the likelihood of chosen responses and reduce the likelihood of rejected responses.
      \item[10.1.2] Train on preference pairs $(x, y_w, y_l)$ without a separate reward model.
    \end{algosublist}
  \item[10.2] Apply a quality gate before accepting an output:
    \begin{algosublist}
      \item[10.2.1] Score each deliverable with the fine-tuned preference model.
      \item[10.2.2] Check instruction following, format, and safety requirements.
    \end{algosublist}
  \item[10.3] Handle quality failures via targeted DAG re-planning:
    \begin{algosublist}
      \item[10.3.1] Record errors when an output fails the quality threshold.
      \item[10.3.2] Send the failed branch back to the planner for targeted revision.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------

\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 11: Artifact Assembly and Global State Commit}

\begin{algolist}
  \item[11.1] Aggregate and assemble multi-agent deliverables:
    \begin{algosublist}

      \item[11.1.2] Combine reports, code changes, and formatted content into one deliverable.
    \end{algosublist}
  \item[11.2] Evaluate the final deliverable for correctness, completeness, and timeliness:
    \begin{algosublist}
      \item[11.2.1] Reject or revise the deliverable if a required dimension is weak.
      \item[11.2.2] Log quality results to improve future routing decisions.
    \end{algosublist}
  \item[11.3] Save the completed session state:
    \begin{algosublist}
      \item[11.3.1] Write conversation records, DAG state, and tool receipts to \texttt{PrismDB}.
      \item[11.3.2] Record latency, token use, and audit information.
    \end{algosublist}
\end{algolist}
\end{frame}

    $\bullet$\enspace\textbf{Connection Basis:} $C$ links to $A$ \& $B$ because its inputs require their outputs; $A$ and $B$ are independent.\\[0.6pt]
    $\bullet$\enspace\textbf{Topological Sorting (Kahn's method):} repeatedly select nodes with $\text{in-degree}=0$, remove outgoing edges, and unlock dependents.\\
    \enspace\enspace This gives a valid dependency order and exposes independent work for parallel execution.\\[0.6pt]
    $\bullet$\enspace\textbf{Execution:} $A$ and $B$ run in parallel; after both finish, $C$ unlocks, then $D$ runs.%

    \begin{algosublist}

% STEP 3: DAG DECOMPOSITION & MODEL ROUTING

\begin{frame}[t]{Algorithm: Step 3 -- Plan and Route the Task}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 3: DAG Decomposition and Model Routing}
\vspace{0.15em}

\begin{algolist}
  \item[3.1] Deconstruct objective into Directed Acyclic Graph $\mathcal{G} = (V, E)$:
    \begin{algosublist}
      \item[3.1.1] Instantiate discrete task vertices $v_i \in V$ with atomic execution contracts and output targets.
      \item[3.1.2] \textbf{Data Dependencies as Directed Edges} ($e = \langle v_i, v_j \rangle \in E \iff \mathcal{O}_i \cap \mathcal{I}_j \neq \emptyset$): Task $v_j$ requires input artifacts produced by $v_i$ (e.g., synthesis requires scraped research).
      \item[3.1.3] \textbf{Execution Barrier:} Consumer $v_j$ remains blocked until producer $v_i$ delivers $\mathcal{O}_i$, guaranteeing tasks never run on missing or partial data.
    \end{algosublist}
  \item[3.2] Compute topological task execution schedule $\pi = \mathrm{TopologicalSort}(\mathcal{G})$:
    \begin{algosublist}
      \item[3.2.1] Identify independent vertices ($\text{in-degree} = 0$) for concurrent parallel dispatch ($K \le 3$).
      \item[3.2.2] Schedule downstream vertices dynamically upon upstream output event emission.
    \end{algosublist}
  \item[3.3] Solve multi-objective provider routing optimization for each sub-task $v_i$:
    \vspace{-0.2em}
    $$\text{Provider}^* = \arg\min_m \Big(\lambda_{\text{cost}} \, \text{Cost}_m + \lambda_{\text{latency}} \, \text{Latency}_m\Big) \quad \text{s.t. } \text{Quality}_m \ge \tau$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Where:}\enspace $\text{Provider}^*$: Optimal LLM backend $\;\vert\;$ $m$: Candidate model $\;\vert\;$ $\text{Cost}_m, \text{Latency}_m$: Normalized price \& delay $\;\vert\;$ $\lambda_{\text{cost}}, \lambda_{\text{latency}}$: Balancing weights $\;\vert\;$ $\tau$: Quality barrier.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[3.3.1] Route high-throughput, latency-critical nodes to LPU backends (Groq / Llama-3).
      \item[3.3.2] Route deep reasoning and code generation tasks to frontier backends (OpenAI GPT-4o, Claude 3.5).
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 4: TASK ASSIGNMENT & AGENT SELECTION
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 4 -- Task Assignment and Agent Selection}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 4: Role-Based Task Assignment and Dispatching}
\vspace{0.15em}

\begin{algolist}
  \item[4.1] Query specialist agent registry and capability profiles:
    \vspace{-0.2em}
    $$\mathcal{A} = \{\text{Planner}, \, \text{Assistant}, \, \text{Researcher}, \, \text{Coder}, \, \text{Validator}\}$$
    \vspace{-0.2em}
    \begin{algosublist}
      \item[4.1.1] Evaluate persona system prompts, specialized instruction boundaries, and assigned MCP tools.
      \item[4.1.2] Verify agent worker availability and monitor concurrent thread utilization.
    \end{algosublist}
  \item[4.2] Execute capability matching algorithm for each sub-task node $v_i$:
    \vspace{-0.2em}
    $$\text{Agent}^* = \arg\max_{a \in \mathcal{A}} \; \mathrm{CosineSimilarity}\big(\mathbf{Req}(v_i), \, \mathbf{Cap}(a)\big)$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Where:}\enspace $\text{Agent}^*$: Assigned specialist persona $\;\vert\;$ $\mathcal{A}$: Swarm agent registry $\;\vert\;$ $\mathbf{Req}(v_i)$: Task requirement vector $\;\vert\;$ $\mathbf{Cap}(a)$: Agent capability embedding $\;\vert\;$ $\mathrm{CosineSimilarity}$: Semantic alignment.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[4.2.1] Match information gathering requirements ($\text{Tag} \ni \texttt{web\_search}$) to Researcher agent.
      \item[4.2.2] Match software synthesis and execution ($\text{Tag} \ni \texttt{python, cli}$) to Coder agent.
      \item[4.2.3] Match quality assurance and policy compliance ($\text{Tag} \ni \texttt{audit, verify}$) to Validator agent.
    \end{algosublist}
  \item[4.3] Manage task lifecycle states in dispatcher queue:
    \begin{algosublist}
      \item[4.3.1] Place sub-tasks in \texttt{PENDING} state until all parent dependency inputs resolve.
      \item[4.3.2] Transition verified nodes to \texttt{READY} and dispatch execution payloads to assigned agents.
    \end{algosublist}
\end{algolist}
\end{frame}

% -----------------------------------------------------------------------------
% STEP 5: AGENT COMMUNICATION & DECISION MAKING
% -----------------------------------------------------------------------------
\begin{frame}[t]{Algorithm: Step 5 -- Agent Communication and Decision Cycle}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 5: Agent Decision Cycle and Inter-Agent Communication}
\vspace{0.15em}

\begin{algolist}
  \item[5.1] Execute autonomous Reasoning-Action (ReAct) cycle for each dispatched agent:
    \vspace{-0.2em}
    $$\text{State } s_t \;\longrightarrow\; \text{\textbf{Observe}} \;\longrightarrow\; \text{\textbf{Reason}} \;\longrightarrow\; \text{\textbf{Act}} \;\longrightarrow\; \text{\textbf{Reflect}}$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Where:}\enspace $s_t$: Current execution state at turn $t$ $\;\vert\;$ \textbf{Observe}: Ingest context \& parent outputs $\mathcal{O}_i$ $\;\vert\;$ \textbf{Reason}: Plan via CoT $\;\vert\;$ \textbf{Act}: Invoke MCP tools $\;\vert\;$ \textbf{Reflect}: Self-correct on error.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[5.1.1] \textbf{Observe:} Ingest assigned sub-task description, operational constraints, and parent inputs.
      \item[5.1.2] \textbf{Reason:} Formulate intermediate chain-of-thought rationale to plan next tool invocation.
      \item[5.1.3] \textbf{Act:} Dispatch structured JSON-RPC tool calls to external MCP servers or formulate text.
      \item[5.1.4] \textbf{Reflect:} Inspect execution exit codes and output schemas; initiate local correction on errors.
    \end{algosublist}
  \item[5.2] Transmit intermediate artifacts via DAG edge message passing:
    \begin{algosublist}
      \item[5.2.1] Route validated producer artifact $\mathcal{O}_i$ directly into consumer input buffer $\mathcal{I}_j$.
      \item[5.2.2] Enforce strict artifact isolation to prevent cross-task context contamination and token inflation.

    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Where:}\enspace $C_{t+1}, C_t$: Next and current context buffers $\;\vert\;$ $\Delta\text{Artifacts}$: Verified upstream deliverables $\mathcal{O}_i$ $\;\vert\;$ $\text{Stale Tokens}$: Discarded scratchpad tokens \& raw tool logs $\;\vert\;$ $\mathrm{Prune}(\cdot)$: Heuristic eviction filter.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[9.2.1] Forward only verified parent output artifacts $\mathcal{O}_i$ to dependent downstream child nodes.
      \item[9.2.2] Evict intermediate reasoning scratchpads, redundant tool telemetry, and discarded draft tokens.
    \end{algosublist}
  \item[9.3] Persist global execution state using client-side database (\texttt{PrismDB}):

    \end{algosublist}

\begin{frame}[t]{Algorithm: Step 10 -- ORPO Preference Model \& Verification}
\vspace{-0.15em}
{\large\bfseries\color{lavenderDark}Step 10: Single-Stage Preference Alignment (ORPO) and Verification}
\vspace{0.15em}

\begin{algolist}
  \item[10.1] Single-stage reference-free preference alignment formulation (ORPO):
    \vspace{-0.25em}
    $$\mathcal{L}_{\mathrm{ORPO}} = \mathcal{L}_{\mathrm{SFT}} + \lambda_{\mathrm{OR}} \cdot \mathcal{L}_{\mathrm{OR}} \quad \text{where} \quad \mathcal{L}_{\mathrm{OR}} = -\log \sigma \left( \log \left[ \frac{\mathrm{odds}_\theta(y_w \mid x)}{\mathrm{odds}_\theta(y_l \mid x)} \right] \right)$$
    \vspace{-0.2em}
    {\footnotesize\color{prismDark}%
      \textbf{\color{lavenderDark}Where:}\enspace $\mathcal{L}_{\mathrm{ORPO}}$: Total loss $\;\vert\;$ $\mathcal{L}_{\mathrm{SFT}}$: SFT cross-entropy loss $\;\vert\;$ $\lambda_{\mathrm{OR}}$: Odds weight $\;\vert\;$ $\mathcal{L}_{\mathrm{OR}}$: Odds ratio penalty $\;\vert\;$ $\mathrm{odds}_\theta(y \mid x) = \frac{P_\theta(y \mid x)}{1 - P_\theta(y \mid x)}$: Output sequence odds $\;\vert\;$ $y_w, y_l$: Chosen / rejected responses for prompt $x$.}
    \vspace{0.15em}
    \begin{algosublist}
      \item[10.1.1] Jointly maximize chosen likelihood while penalizing rejected tokens ($2\times$ memory savings).
      \item[10.1.2] Supervise via UltraFeedback pairs $\mathcal{D} = \{(x, y_w, y_l)\}$, bypassing unstable RLHF loops.
    \end{algosublist}
  \item[10.2] Enforce runtime quality gating via preference score barrier $\mathcal{S}_{\mathrm{ORPO}}(x, y) \ge \tau_{\mathrm{approval}}$:
    \begin{algosublist}
      \item[10.2.1] Audit deliverables using fine-tuned model (\texttt{reward\_orpo\_v2}, Qwen2.5-1.5B LoRA).
      \item[10.2.2] Score candidate outputs on instruction adherence, structural constraints, and safety guardrails.
    \end{algosublist}
  \item[10.3] Handle quality failures via targeted DAG re-planning:
    \begin{algosublist}
      \item[10.3.1] Capture diagnostic error traces and schema deviations when output falls below $\tau_{\mathrm{approval}}$.
      \item[10.3.2] Dispatch error logs to DAG Planner for targeted branch re-planning without system abort.
    \end{algosublist}
\end{algolist}
\end{frame}
