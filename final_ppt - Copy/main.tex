By pairing dynamic multi-model routing (Groq, OpenAI, NVIDIA NIM) with standardized tool access via the \textbf{Model Context Protocol (MCP)}, it coordinates specialized AI swarms to solve everyday and developer workflows-delivering safety-aligned verification and zero-latency local persistence (\texttt{PrismDB}) within a unified, reactive workspace.

\section{Objectives}

\begin{frame}[t]{02. Project Objectives}
\vspace{0.55em}
  \begin{minipage}{0.94\linewidth}
  \fontsize{8.6}{11.2}\selectfont
  \begin{enumerate}\setlength{\itemsep}{12pt}\setlength{\leftmargin}{0.34in}
    \item \textbf{Context-Aware Task Planning:} Convert everyday user goals (communication, file management, daily schedules) and technical requests into structured Directed Acyclic Graphs (DAGs) for organized, dependency-safe execution.
    \item \textbf{Intelligent Model \& Agent Routing:} Dynamically route each sub-task to the most suitable Large Language Model (LLM) backend and dispatch specialized, context-aware agents in parallel.
    \item \textbf{Practical Tool Execution via MCP:} Connect agents to everyday productivity tools and development utilities (Gmail, Google Drive, Filesystem, Terminal CLI, GitHub) through the Model Context Protocol (MCP), accompanied by live Server-Sent Events (SSE) updates.
    \item \textbf{Safety Verification \& Local Persistence:} Validate outputs with human approval checkpoints and Odds Ratio Preference Optimization (ORPO), storing results reactively in local IndexedDB (Indexed Database: \texttt{PrismDB}).
  \end{enumerate}
  \end{minipage}
\end{frame}

\section{System Design}

\begin{frame}[t]{04. System Design Principles}
\vspace{-0.15em}
\begin{itemize}\footnotesize\setlength{\itemsep}{4pt}
  \item \textbf{Layered Decoupling:} Separates the React client UI, FastAPI bridge, and foundation LLMs (each layer has one clear role).
  \item \textbf{Dynamic DAG Scheduling:} Runs dependent sub-tasks in parallel ($K \le 5$; additional tasks are queued) for daily and technical workflows.
  \item \textbf{Standardized Protocol (MCP):} Uses open JSON-RPC tool contracts (a common way for agents and tools to communicate).
  \item \textbf{Human-in-the-Loop:} Sensitive operations require explicit user approval (a safety checkpoint before execution).
  \item \textbf{Local IndexedDB (\texttt{PrismDB}):} ACID browser storage (reliable local data) for sessions, tasks, tool history, and files.
  \item \textbf{Reactive Subscriptions:} Dexie \texttt{useLiveQuery()} updates the UI automatically when data changes.
  \item \textbf{Server-Sent Events (SSE):} Streams tokens and agent telemetry over persistent HTTP (live one-way updates).
  \item \textbf{Calibrated Preference Gating:} ORPO ranks and filters outputs to improve quality and safety.
  \item \textbf{Design Philosophy:} Context-aware, sandboxed, and observable multi-agent workspace (safe and traceable by design).
\end{itemize}
\end{frame}

\section{Swarm Algorithm}
\iffalse
\begin{frame}[t]{Algorithm: Step 1 -- Understand the User Prompt}
\vspace{0.15em}
{\large\bfseries\color{lavenderDark}Step 1: Prompt Understanding}
\vspace{0.25em}
\begin{enumerate}\setlength{\itemsep}{7pt}\large
  \item Read the user's request and identify the main goal.
  \item Extract important details such as files, deadlines, preferences, and restrictions.
  \item Review the conversation history and available project context.
  \item Identify the expected output and any actions that may need user approval.
  \item Create a clear task summary for the planning agent.
\end{enumerate}
\vfill
\centering\color{prismTeal}\textbf{Output: A clear understanding of what the user wants}
\end{frame}

\begin{frame}[t]{Algorithm: Step 2 -- Plan the Task}
\vspace{0.15em}
{\large\bfseries\color{lavenderDark}Step 2: Task Planning and Routing}
\vspace{0.25em}
\begin{enumerate}\setlength{\itemsep}{7pt}\large
  \item Break the request into smaller tasks.
  \item Decide which tasks can run at the same time and which depend on earlier results.
  \item Select the most suitable agent for each task.
  \item Choose the model or service based on the task's speed, complexity, and cost.
  \item Create an execution plan and send each task to the assigned agent.
\end{enumerate}
\vfill
\centering\color{prismTeal}\textbf{Output: An ordered task plan for the agent team}
\end{frame}

\begin{frame}[t]{Algorithm: Step 3 -- Coordinate the Agents}
\vspace{0.15em}
{\large\bfseries\color{lavenderDark}Step 3: Swarm Agent Collaboration}
\vspace{0.25em}
\begin{enumerate}\setlength{\itemsep}{7pt}\large
  \item The Planner Agent organizes the work and tracks progress.
  \item The Assistant Agent handles everyday tasks such as email and documents.
  \item The Code Agent creates, edits, and checks code when needed.
  \item The Research Agent gathers relevant information from approved sources.
  \item The Reviewer Agent checks intermediate results and shares feedback with the team.
\end{enumerate}
\vfill
\centering\color{prismTeal}\textbf{Output: Completed sub tasks with shared context}
\end{frame}

\begin{frame}[t]{Algorithm: Step 4 -- Use MCP Tools}
\vspace{0.15em}
{\large\bfseries\color{lavenderDark}Step 4: Tool Execution through MCP Servers}
\vspace{0.25em}
\begin{enumerate}\setlength{\itemsep}{7pt}\large
  \item The assigned agent requests the required tool through the MCP server.
  \item Gmail is used for email tasks and Google Drive for document tasks.
  \item Filesystem tools read, organize, and save local project files.
  \item Terminal and web tools support approved commands, testing, and information lookup.
  \item Sensitive actions such as sending email or changing files wait for approval when required.
\end{enumerate}
\vfill
\centering\color{prismTeal}\textbf{Output: Tool results returned to the responsible agent}
\end{frame}

\begin{frame}[t]{Algorithm: Step 5 -- Verify and Deliver}
\vspace{0.15em}
{\large\bfseries\color{lavenderDark}Step 5: Validation, Retry, and Delivery}
\vspace{0.25em}
\begin{enumerate}\setlength{\itemsep}{7pt}\large
  \item The Validator Agent checks accuracy, completeness, and policy safety.
  \item If a result is incomplete or incorrect, the task is sent back for correction.
  \item Approved results are combined into one final response or deliverable.
  \item Progress and final output are streamed live to the user.
  \item The completed task and useful context are saved in PrismDB for later use.
\end{enumerate}
\vfill
\centering\color{prismTeal}\textbf{Output: Verified deliverable, live updates, and saved task state}
\end{frame}

\begin{frame}[t]{Algorithm: Step 1 -- Understand the User Prompt}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 1: Prompt Understanding}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Goal \& Intent Identification:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Reads natural-language request and extracts the primary user objective.
      \item Incorporates previous conversation turns and project context from PrismDB.
    \end{itemize}
  \item \textbf{Constraint \& Context Formalization:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Extracts operational constraints, local files, deadlines, and expected deliverables.
      \item \textbf{Task Tuple Representation:} Formalized as:
        $$T = (G, C, X, R, O)$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This formalizes unstructured user requests into an operational execution tuple, where $T$ is the task representation, $G$ is the user goal, $C$ are operational constraints, $X$ is conversation context, $R$ are available tool resources, and $O$ is the expected deliverable output format.
        }
    \end{itemize}
  \item \textbf{Safety Screening \& Router Hand-off:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Detects if request requires external MCP tools, human approval, or extra clarification.
      \item \textbf{Methods Used:} NLU parsing for intent extraction, semantic vector retrieval for context matching, and lexical feature scoring.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 2 -- Classify the Request}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 2: Intent and Requirement Analysis}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Multi-Class Intent Categorization:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Maps request into 12 distinct task classes (everyday, document, research, code, mixed).
      \item \textbf{Optimal Class Selection:} Formulated via maximum posterior probability:
        $$c^* = \arg\max_{c \in \mathcal{C}} P(c \mid x)$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This predicts the most probable intent class to determine specialized routing, where $c^*$ is the chosen category, $\mathcal{C}$ is the set of 12 candidate classes, $P(c \mid x)$ is the class posterior probability, and $x$ is the extracted 10k TF-IDF lexical and token prompt feature vector.
        }
    \end{itemize}
  \item \textbf{Capability \& Action Boundary Profiling:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Identifies required capabilities: file I/O, search, synthesis, computation, or communication.
      \item Classifies action types into safe read-only, state-modifying, or sensitive operations.
    \end{itemize}
  \item \textbf{Risk Assessment \& Safety Screening:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Evaluates complexity, execution urgency, and initial risk levels.
      \item \textbf{Methods Used:} Supervised classification, keyword extraction, and rule-based gating.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 3 -- Plan and Route the Task}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 3: Task Decomposition and Model Routing}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{DAG Workflow Construction:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Decomposes compound request into modular sub-tasks with dependency constraints.
      \item Generates Directed Acyclic Graph $\mathcal{G}(V, E)$ via topological sorting for parallel execution.
    \end{itemize}
  \item \textbf{Multi-Provider Cost/Latency Optimization:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Routes sub-tasks to Groq (ultra-low latency), OpenAI (reasoning), or NVIDIA NIM.
      \item \textbf{Objective Function:}
        $$m^* = \arg\min_m \left(\lambda_c C_m + \lambda_l L_m\right) \quad \text{s.t.} \quad Q_m \ge \tau_Q$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This selects the optimal provider $m^*$ minimizing weighted monetary cost $C_m$ and latency $L_m$ with trade-off weights $\lambda_c, \lambda_l$, subject to predicted quality score $Q_m$ meeting minimum acceptable threshold $\tau_Q$.
        }
    \end{itemize}
  \item \textbf{Concurrency Dispatch:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Dispatches zero-in-degree dependency-safe tasks concurrently across allocated providers.
      \item \textbf{Methods Used:} Topological sorting, multi-criteria provider routing, and Pareto optimization.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 4 -- Select the Agent Team}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 4: Swarm Agent Selection}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Specialist Agent Allocation:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Matches sub-tasks to designated worker roles: \textit{Planner, Assistant, Researcher, Coder, Reviewer}.
      \item \textbf{Agent Assignment Function:} Evaluates capability alignment across candidate agent pool $\mathcal{A}$:
        $$a^* = \arg\max_{a \in \mathcal{A}} \mathrm{Match}(a, \, \text{Requirements})$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This selects and assigns the best-fitting specialist agent $a^*$ from candidate pool $\mathcal{A}$, where $\mathrm{Match}(\cdot)$ evaluates capability and skill alignment against extracted sub-task requirements.
        }
    \end{itemize}
  \item \textbf{Specialist Role Responsibilities:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item \textit{Assistant}: Communications \& docs; \textit{Researcher \& Coder}: Artifact synthesis; \textit{Reviewer}: Validation.
    \end{itemize}
  \item \textbf{Swarm Collaboration Mechanics:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Binds agents with shared memory context and synchronized DAG state.
      \item \textbf{Methods Used:} Role-based routing, capability matching, and parallel swarm dispatch.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 5 -- Execute with MCP Tools}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 5: ReAct Reasoning and MCP Tool Use}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{ReAct Decision Cycle:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Executes continuous reasoning cycle: $\text{Observation} \to \text{Thought} \to \text{Action} \to \text{Observation}$.
      \item \textbf{Action Value Optimization:} Selects maximum expected-utility action for state $s_t$:
        $$a_t = \arg\max_a Q(s_t, a)$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This selects the optimal tool invocation or reasoning action $a_t$ maximizing expected progress toward goal completion, where $s_t$ is the current execution state and $Q(s_t, a)$ evaluates expected action utility.
        }
    \end{itemize}
  \item \textbf{Standardized MCP Server Invocation:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Interacts with local tools via JSON-RPC: Gmail, Drive, Filesystem, Terminal CLI, GitHub.
      \item Ingests tool outputs back into agent context for downstream reasoning iterations.
    \end{itemize}
  \item \textbf{Human-in-the-Loop Safeguards:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Pauses execution before state-mutating or high-risk actions pending explicit human approval.
      \item \textbf{Methods Used:} ReAct prompting, MCP JSON-RPC schemas, and sandboxed action isolation.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 6 -- Share Context and Memory}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 6: Context Synchronization}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Inter-Agent State Propagation:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Transfers completed sub-task outputs to dependent downstream agents along DAG edges.
      \item Preserves global user intent, constraints, and decision logs across all transitions.
    \end{itemize}
  \item \textbf{Dynamic Context Compaction:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Deduplicates intermediate chatter and prunes obsolete context to stay within token limits.
      \item \textbf{Context Update Equation:} Formalized state update with compaction:
        $$C_{t+1} = \mathrm{Compress}\big(C_t \cup \Delta C_t \setminus D_t\big)$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This maintains shared memory across agents while compacting tokens to prevent context overflow, where $C_{t+1}$ is updated context for step $t+1$, $C_t$ is active context, $\Delta C_t$ are new tool outputs, $D_t$ are evicted obsolete tokens, and $\mathrm{Compress}(\cdot)$ performs pruning and deduplication.
        }
    \end{itemize}
  \item \textbf{Reactive Local Storage:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Writes state changes atomically to browser IndexedDB via Dexie.js (\texttt{PrismDB}).
      \item \textbf{Methods Used:} Shared-memory caching, token pruning, and atomic persistence.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 7 -- Validate and Retry}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 7: Verification and Safety}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Multi-Criteria Output Auditing:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Reviews deliverables against original goal, formatting constraints, and safety guidelines.
      \item Evaluates action outputs with IsolationForest anomaly detection and WildGuardMix checks.
    \end{itemize}
  \item \textbf{Composite Safety \& Alignment Gating:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Scores outputs against human preference via Qwen ORPO alignment reward model.
      \item \textbf{Approval Gating Condition:} Only permits completion if composite score passes threshold:
        $$S = \sum_{i} w_i \, q_i \ge \tau_{\text{safety}}$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This enforces a strict quality and safety barrier before release, where $S$ is the composite score, $q_i$ are individual criterion scores (correctness, completeness, WildGuardMix safety, ORPO preference), $w_i$ are relative importance weights ($\sum w_i = 1$), and $\tau_{\text{safety}}$ is the approval threshold.
        }
    \end{itemize}
  \item \textbf{Corrective Re-plan Loop:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item If verification fails, routes task back to the DAG Planner with feedback for targeted retry.
      \item \textbf{Methods Used:} ORPO preference scoring, anomaly isolation, and automated re-planning loops.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}[t]{Algorithm: Step 8 -- Deliver and Monitor}
\vspace{0.20em}
{\large\bfseries\color{lavenderDark}Step 8: Verified Delivery and Monitoring}
\vspace{0.35em}
\begin{itemize}\setlength{\itemsep}{4pt}
  \item \textbf{Result Synthesis \& Live Streaming:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Assembles verified sub-task outputs into final deliverables (emails, code, reports).
      \item Streams real-time progress, intermediate logs, and final answers to UI via Server-Sent Events (SSE).
    \end{itemize}
  \item \textbf{End-to-End Quality Assessment:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Evaluates holistic delivery performance across execution metrics.
      \item \textbf{Delivery Score Formulation:} Multiplicative composite metric:
        $$D = \mathrm{Correctness} \times \mathrm{Completeness} \times \mathrm{Timeliness}$$
        \vspace{-0.3em}
        {\footnotesize\color{prismDark}
        This assesses holistic delivery quality such that failure in any single dimension penalizes overall score $D$, where $\mathrm{Correctness}$ measures accuracy, $\mathrm{Completeness}$ measures task fulfillment, and $\mathrm{Timeliness}$ measures turnaround speed relative to deadline.
        }
    \end{itemize}
  \item \textbf{Persistence \& Continuous Learning:}
    \begin{itemize}\setlength{\itemsep}{2pt}
      \item Persists conversation, DAG nodes, and tool outputs into Dexie.js (\texttt{PrismDB}).
      \item Records latency, costs, and approval patterns for offline model retraining.
      \item \textbf{Methods Used:} SSE streaming, reactive Dexie persistence, and telemetry collection.
    \end{itemize}
\end{itemize}
\end{frame}
